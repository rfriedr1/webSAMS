Navigate

SAMS gives you four ways to jump around — pick whichever one fits the moment.

  • Magic Nav (top bar): type an ID and press Open. Click the small ? next to the input for the syntax cheat sheet, or see the patterns below.

    • {{ rule.example }} — {{ rule.description }}
      • {% endfor %}
    • /prep · /graph · /ana · /ea jump to the matching Lab page (/ea = EA Checks).
    • /sub · /proj · /import jump to Submitters, Projects, and Sample Import.
    • A command always starts with /, so /sub (the submitter list) and sub:210 (submitter 210's record) are different things.
    • Prefixes follow one rule: prefix, optional separator, value. Digits are a number, a value starting with a letter is a name — sub:210, sub210 and sub 210 are the same, as are sub:meier and sub meier.
    • A last-name lookup ignores case and accents (sub:hack finds Häck). Exact last names win over partial ones, so sub:roth opens the only Roth even when there are Rothe records. When several records match — different people, or one person stored with several addresses — the submitter list opens filtered to that name, with organisation, town and e-mail to tell them apart.
  • Command palette: press Ctrl/⌘ K (or click Jump in the top bar) to open a full-text search across every page, magic command, pinned page, and recent page. Arrow keys to move, Enter to open, Esc to close.
  • Pinned & Recent: the line under the top bar shows where you are on the left and your pinned and recently visited pages on the right. Click ☆ Pin to pin the current page (or press Ctrl/⌘ Shift P); up to 12 stay pinned until you unpin them. Recent shows the last few pages you opened (all of the last 8 are in the command palette).
  • Detail page arrows: on a record, the small ‹ / › step to the previous / next record. Or press [ / ] (or j / k) for the same.
  • Sample photos: a sample page shows every photo in the lab's photo folder whose file name starts with the sample number (48211.jpg, 48211b.jpg, …). Click a thumbnail to open the viewer: scroll or + / − to zoom, drag to pan, double-click or 1 for actual size, 0 to fit, ← / → for the other photos, Esc to close. A photo of several samples appears on each of them (25328-25337.jpg, 11584-7.jpg, 16191_16192.jpg) and carries a Group photo badge. The download icon saves the original file. Just added a photo? Click the refresh icon next to Photos. If the photo folder cannot be reached, the Photos box says why (e.g. file server unreachable, access refused, too many connections) and what to do, with a Try again button.
  • Back: every detail page has a Back link that returns to where you came from, falling back to a sensible default (e.g. the project listing) if the browser history doesn't match.

Edit

All detail pages (sample, preparation, target, project, submitter) work the same way. There is no edit mode: you change a value where you see it.

  • Change a value: click it (a pencil shows on hover) or reach it with Tab. It turns into its input in place. Esc undoes the change in that field. Values shown without a pencil (numbers, results owned by BATS, calculated values) cannot be changed here.
  • Change several values, save once: changed fields stay open with a dot next to their label, and a bar at the foot of the record counts them (3 unsaved changes). Save (Ctrl/⌘ S) stores them all together; Cancel drops them all. Only the fields you changed are sent.
  • Empty fields: fields without a value are folded away under N empty fields hidden. Click that line to show them, then click one to fill it in.
  • Unsaved changes: if you try to leave the record with changes, SAMS asks whether to Discard, Save, or Keep editing — your work is never lost silently. If a save is refused, your changes stay on the page, still marked, next to the reason.
  • Save status: after a save, the record header shows a green Saved · just now hint that updates relative time as you keep working.
  • View only: an account that may only view sees the same page without pencils or the save bar.
  • Warnings: when a value falls outside a Lab Warning Threshold (see Settings), the affected card turns red and an inline hint explains what's off.

All keyboard shortcuts on a detail page:

  • Click or Tab — open a field to change it
  • Esc — undo the change in the open field (or close the unsaved-changes prompt)
  • Ctrl/⌘ S — save all changes
  • [ / j — previous record
  • ] / k — next record
  • ? — open the cheat-sheet overlay (same content, on top of the current page)

Shortcuts are suppressed while you're typing in an input — except Save, which always works.

Change many records at once

Project and submitter pages have an Actions button in their header. It sets or clears one value on many records in one go — for example C/N isotope analysis on every sample of a project, instead of opening each sample.

  • Which records: tick rows in the table under the record (a project's samples, a submitter's projects). Nothing ticked means all of them. The tick box in the table head ticks the rows the table filter shows, so filter “bone”, tick all, run works.
  • Preview first: choosing an action shows what will change (number, label, old → new), how many already have the value, and any warning. Nothing is saved until you press the button at the foot of that window.
  • Records that cannot be changed: a record its own page would refuse to save (an old sample without a Type, say) is listed with the reason and left as it is; the rest are saved.
  • Storage locations (project page): Edit lists the samples with their current Sample or Prep Storage Location in a box each. Change single boxes, or type into Fill all to give every sample the same value; Enter moves to the next box. Only changed boxes are saved, and an emptied box clears the value.
  • Undo: every flag action comes as a Set / Clear pair — run the other one on the same rows. Storage locations have no undo besides editing them back.
  • From the command palette: on a project or submitter page, ⌘K lists the actions as Action: ….

Import samples from Excel

Samples → Import takes a filled-in submission workbook (.xlsx) and creates the project and all its samples in one go. Five steps: Upload → Review & fix → Lab values → Extra analyses → Imported. Nothing is written to the database until you press Import samples at the end of step 4.

  • Layout is flexible. Columns are found by their headings, so the customer may rename, reorder, or add columns without breaking the import. Anything unrecognised is kept and shown under Column mapping, where you can map it yourself or leave it out.
  • Submitter and invoice recipient are matched separately. Returning customers are scored on e-mail, name and organisation, with the reasons shown. Confirm the match, use Browse all submitters to search the whole address book, or choose Create a new submitter and fill in the full contact record (salutation, title, language, comment — the language decides which confirmation-mail template is used). If the sheet carries a separate billing address, the same picker appears for the invoice recipient.
  • Duplicate projects are caught. If the submitter already has a project with the same or a similar name, you're asked whether to add the samples to that project (its settings stay untouched) or to create a separate one — with a suggested Name_Month_Year variant. Project type, research field, report type, supervisor and priority come from the lab's own lists; the free-of-charge and return-of-material flags are tick boxes.
  • Lab values are yours, not the customer's. Step 3 groups the rows by the material the customer wrote (collagen, charcoal, …) and lets you set the lab's own type, material and fraction plus preparation steps 1–5 for a whole group at once. Close spellings are offered as suggestion chips — only an exact match is filled in for you, so a guess is never made on your behalf. For anything that doesn't fit a group, tick the rows you want and use Apply to selected, or edit a single row inline. Unresolved lookups are saved as undefined rather than as free text.
  • Everything is editable before import. Correct any cell in the preview, untick rows you don't want, and adjust the project name and dates. The Import samples button stays disabled until the listed problems are fixed.
  • What gets created: the submitter (if new), the project, one sample per row, and for each sample a preparation #1 carrying its prep steps plus an empty target #1. If anything fails, nothing is written at all.
  • Check the mail settings first. Setup → E-mail has a Send a test e-mail box: type any address, press the button, and SAMS delivers one short message using the settings as currently typed — so you can verify them before saving. Leave the password blank to reuse the stored one.
  • Extra analyses are set by hand. Step 4 shows the samples again so you can request C/N isotope analysis and Dendro analysis beyond C14 dating — for all samples at once (All / None) or per sample. Both default to off; the submission sheet does not carry them.
  • The confirmation e-mail is never sent by itself. After the import, step 5 shows the finished message — recipient, subject, and the body pairing each new MAMS-… number with the customer's own label. Edit it, skip it, or press Send. Server settings and the per-language templates live in Setup → E-mail; until a mail server is configured, Send stays disabled.
  • Teaching the importer a new column needs no developer. Setup → Import Column Headings lets you add extra spellings for the fields SAMS already knows, and define entirely new columns by picking the sample field the value should land in. The next import picks them up automatically.
  • Need the blank form to send a customer? Download the template from the upload step.

EA checks (acetanilide)

  • Log the daily check in the EA checks today strip at the top of Lab → Graphitization or Lab → EA Checks (/ea): type C % and N % (comma or point) — or drag the needle, click on the gauge, use the mouse wheel or the arrow keys (0.1 per step). Pick your name and press Enter. The field turns green inside the pass window and red outside it.
  • Out of the window? The check is still logged as failed, with a short comment on what you will do. Re-run as often as needed — the EA's status for the day is its latest check. The Graph Batch Builder marks systems whose EA has no passing check yet, but never blocks.
  • Typed a wrong number? Void it with the × in the history table (reason required). Nothing is ever deleted; signed-off checks can no longer be voided.
  • Sign-off: the lab director opens Review & sign off on the EA Checks page, sees exactly the unsigned checks with their statistics (mean, s, bias, failures) and signs with a verdict. Each sign-off has a printable record for the audit binder. Analyzers, check standards and who may sign are set in Setup → EA Checks and Lab Staff.

Find

  • Tables have a search box (substring match across all visible columns) and a Column dropdown to scope the search. Click a column header to sort; click again to reverse. On large tables (200+ rows) you'll see a row-count badge and a hint to filter — typing in the search is much faster than scrolling.
  • Table export: click the ↓ icon to download the currently-visible rows as Excel-compatible XML.
  • Global search: the Search page (top nav) takes a context (Submitter / Project / Sample / Preparation / Target) and a phrase. Results are clickable and inherit the table's search/sort/export tools.

Feedback & status

  • Toasts (top-right) confirm one-off actions like Save, Pin, and bench commits. They auto-dismiss after ~4.5 seconds.
  • Saved hint (next to Edit/Save) persists after a save so you can confirm at a glance — even if you missed the toast.
  • Progress bar (top of viewport) sweeps during navigation and form submission.
  • Error summary: if Save fails, a banner at the top of the detail page lists every failing field with a click-to-jump link.

Settings

The Setup page is the central place for system-level configuration that should be changeable without editing code.

  • Standard Inventory Thresholds — controls the warning colours on the dashboard standards row and mini-bars. Hover a dashboard card for the active rule.
  • Graphitization Systems — the selectable systems used in the Graphitization Bench batch builder. One entry per line.
  • Lab Warning Thresholds — the per-field warning rules that highlight detail-page cards (e.g. Total C below 500 µg, Yield below 0.5 %). New thresholds added here automatically surface on the matching detail pages.
  • Sample Photos — the shared folder the sample photos are read from, with a folder check that reports how many photos were found.

Settings persist in setup_data.json and are applied when the related pages load.
